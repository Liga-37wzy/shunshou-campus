# 顺手校园：校园互助与物品流通平台

## 一句话介绍

把需要帮忙的学生与刚好顺路的学生连接起来，让跑腿、易物和失物归还在同一个平台完成，并逐步延伸到线下校园服务站。

## 故事从哪里开始

一名学生正在赶课，快递却放在南门；另一名学生刚好从南门回宿舍。两人之间缺少的不是配送能力，而是一个可信、清楚的对接过程。

同样的问题也发生在闲置交换和失物归还中：物品不远，交接却麻烦。顺手校园从“把一件东西顺路带过去”切入，将校园里的人员流动变成更便利的生活服务。

## 产品与创新

1. **行程驱动接单**：先提交自己的出发地、目的地与空闲时间，再获得有解释的订单推荐。希望降低接单者额外走路的成本，而不是要求学生全天候待命。
2. **易物配送联动**：交换申请和配送任务彼此关联，交换双方都确认收到物品才完成，解决“谈好了但交接难”的问题。
3. **线上线下共用流程**：服务站承接人员集结、暂存、交接与认领。线上记录帮助线下协作；服务站并非初期必须投入的固定成本。

目前提供响应式 Web 原型，之后按试点反馈决定是否开发微信小程序，再考虑独立 App。未来终端可以复用业务模型，但微信登录、通知、支付及接口认证仍需专门适配。

## 用户与服务

| 用户 | 需要 | 平台提供 |
|---|---|---|
| 有委托的学生 | 及时找到愿意帮忙的人 | 发单、费用展示、进度、交付确认 |
| 愿意接单的学生 | 灵活利用空闲与顺路行程 | 推荐任务、自愿接单、收入预估 |
| 有闲置物品的学生 | 方便交换与交接 | 易物提议、双方确认、配送关联 |
| 拾获者与失主 | 方便且可信地归还 | 公开信息、私密线索、核验记录 |
| 校区运营与站点人员 | 处理审核、交接和异常 | 分角色管理，后续补充纠纷与审计工具 |

## 商业模式

以自愿接单的撮合模式起步，不自建固定配送团队。订单服务费用于覆盖维护、客服和运营。原型采用“服务报酬的 10%，上限 2 元”演示规则，尚未验证该价格的市场接受度，也未实际收费。

易物信息与失物招领保持低门槛。易物产生的配送单按规则计费；后续可探索获许可的服务站合作、社团批量代办等，不把未经验证的收入写成既成事实。

低固定人力成本不意味着没有成本：服务器、支付通道、客服、纠纷处理、场地和人员管理都需要预算。作为平台仍需承担自身的信息管理、服务承诺和纠纷处理责任，不能用“只是中介”一概免责。

## 从一个校区做大

| 阶段 | 做什么 | 进入下一阶段前观察什么 |
|---|---|---|
| 课程验证 | 运行原型、展示完整流程、访谈潜在用户 | 真实需求频次、是否愿意接单、最常见交接障碍 |
| 小范围试点 | 在取得必要同意后选择 2—3 栋宿舍，集中时段运营 | 接单耗时、履约率、争议率、每单成本与重复使用 |
| 全校推广 | 增加身份核验、通知、支付、客服和校区运营后台 | 供需能否稳定、净收入能否覆盖运营成本 |
| 线下服务站 | 优先借用或合作已有空间，尝试休息、交接、暂存 | 使用频次、保管压力、场地与值守成本 |
| 多校复制 | 每校独立运营与权限隔离，总部提供技术与规则 | 单校流程是否标准化，跨校权限和结算是否可靠 |

## 试点评价

项目优势是场景集中、需求与接单时间有机会匹配，以及易物和线下交接可以共用订单能力。主要不确定性是订单密度、付费意愿、可信供给和客服成本。

下一步应通过访谈与小范围试点验证这些假设，而不是直接假设“全体学生都是客户”“供给会自动出现”或“必然高利润”。
